# Frame flash limiter passes

Portable GLSL for the frame flash limiter: seven fragment passes that hold back any part of the
frame whose luminance or red transitions would exceed the flash-area limit. They reproduce the
reference model `tools/shader/limiter-model.mjs` (model `subblock-10deg`) bit for bit. The
conformance vectors in `conformance/limiter/frame/` are the spec. `make limiter-check` checks the
model, the generated GLSL ES 3.00 and Metal, and the WebGL2 and Metal passes against those vectors.

`tools/shader/limiter.mjs` wraps each pass the way `present.mjs` wraps the present pass:

- GLSL ES 3.00 for WebGL2;
- GLSL 450 through glslangValidator and SPIRV-Cross (pinned) to Metal, with the ABI checked.

Each pass is `luma-lut.glsl` (rows only), then `common.glsl`, then `<pass>.glsl`.
`luma-lut.glsl` is generated by `node tools/shader/limiter.mjs --write`; do not hand-edit it.

## Bindings

| Resource | WebGL2 | Metal |
|---|---|---|
| `LimiterBlock` (32 bytes, std140) | uniform block, binding 0 | `[[buffer(0)]]` |
| Textures, in the order listed per pass | units 0.. | `[[texture(0..)]]` |
| Sampler | none: every read is `texelFetch` | `[[sampler(0)]]`, any state |
| Outputs | `location` 0.. | `[[color(0..)]]` |

The uniform block holds two vectors:

- `limiter0 = (cols, rows, limit, refill)`
  - `cols` and `rows` are the window size in cells.
  - `limit` is the area limit in sub-blocks; a window is over when its count is strictly greater.
  - `refill` is the token refill this frame, `floor(clamp(2 * maxFlashHz * dt, 0, 1) * 65025)`.
- `limiter1 = (tick, deltaMs, 0, 0)`
  - `tick` is `floor(ms / (1000/15/64)) mod 255`.
  - `deltaMs` is the frame interval as float32.

`windowOf(geometry)` in `tools/shader/limiter-geometry.mjs` gives `cols`, `rows` and `limit` for
a device class. `createClock` in the model gives `tick`, `deltaMs` and `refill`.

## Texture formats

| Type | WebGL2 | Metal |
|---|---|---|
| frame, history, output | RGBA8 | `rgba8Unorm` |
| row partial sums | RGBA32UI | `rgba32Uint` |
| every other state texture | RGBA16UI | `rgba16Uint` |

## Passes

Run the passes in order each frame. Each pass draws one full-screen triangle into a framebuffer
of the size shown. The entry point is `oscillux_limiter_<pass>`.

| # | Pass | Size | Textures | Outputs |
|---|---|---|---|---|
| 1 | `rows` | 64 x frame height | `uFrame` | `oR` (RGBA32UI): per sub-block column and pixel row, the luma sum, linear-light red-excess sum, pixel count |
| 2 | `reduce` | 64 x 36 | `uRows`, `uT0`, `uT1` | `oS` = (luma code, red code, request bits, 0) |
| 3 | `cells` | 16 x 9 | `uS`, `uT2` | `oC`: per direction, the count (0..16) of sub-blocks requesting now or within the coverage interval, \| requests << 5 |
| 4 | `windows` | 16 x 9 | `uC` | `oW`: per direction, an over bit for the window with its origin at this cell |
| 5 | `grant` | 1 x 1 | `uC`, `uW`, `uG` (previous) | `oG` = (admitted bits \| over bits << 4, token deficit, 0, 0) |
| 6 | `state` | 64 x 36 | `uS`, `uG` (this frame), `uT0`, `uT1`, `uT2` | `oT0`, `oT1`, `oT2` |
| 7 | `output` | frame | `uFrame`, `uHist` (previous output), `uT1` (this frame) | `oColor` |

Directions are bit 0 luma rising, bit 1 luma falling, bit 2 red rising, bit 3 red falling.

The `grant` pass applies the red-0 rule: red over the limit is never admitted. It has no token
of its own, so red never takes or waits for the luma token. Luma over the limit takes the single
token when the deficit is zero.

## State and ping-pong

The tracker state is three 64 x 36 RGBA16UI textures:

- `T0` holds the trackers' low and high marks.
- `T1` holds (luma direction + 1, red direction + 1, live, hold). The `output` pass reads the
  `w` of a pixel's sub-block and of its eight neighbours: a held sub-block shows history, and a
  sub-block beside one blends toward history, so a hold has no hard edge (red-dominant pixels are
  never blended).
- `T2` holds the recency stamps (tick + 1; 0 means none).

Keep two copies each of `G`, `T0`, `T1`, `T2` and the output. A frame reads copy `a` and writes
copy `b`, then the host swaps them. `grant` and `state` read this frame's `G` (copy `b`), and
`output` reads this frame's `T1`.

`rows`, `reduce`, `cells` and `windows` write single textures that are rebuilt every frame.

At start, and whenever the frame size or geometry changes, the host clears every state and
history texture to zero. After a clear no sub-block is tracked, and the first frame passes
through unchanged.

None of the passes allocate. A host creates the textures once per frame size.

## Cost

Measured with `node tools/shader/limiter-check.mjs --metal --time 1920x1080`. On an M2 Max the passes cost 0.22 ms of GPU time
per frame at 1080p and 0.47 ms at 4K. The `rows` and `output` passes scale with resolution; the
rest are fixed size.
